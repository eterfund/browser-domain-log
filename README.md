# Журнал внешних доменов браузера

Один готовый файл `browser-domain-log.js`, без сборки, npm и сторонних сервисов. Подключается на страницах, где нужно расследовать неожиданные переходы. nginx принимает короткий POST для каждого события и пишет одну строку JSON.

### Подключение

1. Скопируйте `browser-domain-log.js` в каталог сайта, доступный как `/static/browser-domain-log.js`.
2. В секции `http` nginx объявите формат журнала.

   ```nginx
   log_format browser_domain escape=json
       '{"time":"$time_iso8601","visit":"$arg_visit","ms":"$arg_ms",'
       '"event":"$arg_event","host":"$arg_host","kind":"$arg_kind"}';
   ```

3. В существующий HTTPS-блок `server` сайта добавьте точный адрес приёмника. Путь журнала подберите с учётом размещения и ротации логов сайта.

   ```nginx
   location = /_browser-event {
       if ($request_method != POST) { return 405; }
       access_log /var/log/nginx/browser-domain.jsonl browser_domain;
       return 204;
   }
   ```

4. Проверьте конфигурацию с помощью `nginx -t` и перечитайте её. В начале `<head>` страниц раздела, перед скриптами приложения, подключите файл.

   ```html
   <script src="/static/browser-domain-log.js"></script>
   ```

   Для другого пути приёмника задайте `data-endpoint="/другой-путь"` и такой же `location` в nginx. Скрипт и приёмник должны быть доступны с сайта. При наличии CSP разрешите их в действующих `script-src` и `connect-src`.

### Проверка и чтение журнала

Откройте страницу в новой вкладке и нажмите на внутреннюю ссылку. В сети браузера должен появиться POST на `/_browser-event` с ответом 204, в журнале — `first_click` с хостом сайта. При клике вне ссылки поле `host` пустое. Внешний ресурс даст отдельное событие `resource` для каждой пары «хост, тип ресурса». Записи можно смотреть так:

```sh
tail -f /var/log/nginx/browser-domain.jsonl | jq -c .
```

Для расследования сгруппируйте записи по `visit`, случайному идентификатору одной загрузки страницы, и отсортируйте по числовому значению `ms` (миллисекунды с начала навигации). Скрипт регистрирует также последующие клики по внешним ссылкам (`external_click`), видимые браузеру попытки внешней навигации (`navigate`, при поддержке Navigation API) и вызовы `window.open` с внешним HTTP(S)-адресом в виде строки (`window_open`). Попытка открытия может быть заблокирована браузером.

В журнал передаются имена хостов, без путей и параметров ссылок. Наблюдатель видит записи Resource Timing текущего документа. Запросы внутри чужого iframe, дальнейшие редиректы на чужом сайте и переход через промежуточную пустую вкладку могут остаться невидимыми. Доставка событий при закрытии страницы также не гарантируется. Публичный приёмник принимает данные от клиента, поэтому отдельная запись требует подтверждения при расследовании.
